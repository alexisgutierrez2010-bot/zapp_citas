INSTRUCCIONES DE DESPLIEGUE - ZAPP CITAS
==================================================

Fecha: 24 de Noviembre de 2025

Este documento proporciona los pasos b&aacute;sicos para desplegar la aplicaci&oacute;n ZApp Citas desde un entorno local (XAMPP en Windows) a un servidor de hosting en producci&oacute;n (como Hostinger, basado en Linux).

----------------------------------------
1. REQUISITOS DEL SERVIDOR
----------------------------------------

Aseg&uacute;rate de que tu plan de hosting cumpla con los siguientes requisitos:

- **Servidor Web:** Apache o Nginx.
- **PHP:** Versi&oacute;n 8.0 o superior.
- **Extensiones de PHP:**
  - `mysqli` (para la conexi&oacute;n a la base de datos).
  - `json` (para el manejo de las APIs).
  - `mbstring` (para el manejo de caracteres multibyte).
  (Estas extensiones suelen estar activadas por defecto en la mayor&iacute;a de los hostings modernos).
- **Base de Datos:** MySQL o MariaDB.

----------------------------------------
2. PREPARACI&Oacute;N DE LA BASE DE DATOS
----------------------------------------

1.  **Exportar la Base de Datos Local:**
    - Abre phpMyAdmin en tu XAMPP.
    - Selecciona la base de datos `u802326406_citas`.
    - Ve a la pesta&ntilde;a "Exportar".
    - Elige el m&eacute;todo "R&aacute;pido" y el formato "SQL".
    - Haz clic en "Exportar" para descargar el archivo `.sql` a tu computadora.

2.  **Crear e Importar la Base de Datos en el Hosting:**
    - En el panel de control de tu hosting (ej. hPanel de Hostinger), ve a la secci&oacute;n de "Bases de Datos".
    - Crea una **nueva base de datos** y un **nuevo usuario** para esa base de datos. Anota cuidadosamente el nombre de la base de datos, el nombre de usuario y la contrase&ntilde;a que generes.
    - Abre phpMyAdmin en tu hosting y selecciona la base de datos que acabas de crear.
    - Ve a la pesta&ntilde;a "Importar", selecciona el archivo `.sql` que exportaste de tu XAMPP y ejecuta la importaci&oacute;n.

----------------------------------------
3. CONFIGURACI&Oacute;N DEL PROYECTO
----------------------------------------

Este es el paso m&aacute;s cr&iacute;tico. Antes de subir los archivos, debes editar el siguiente archivo en tu computadora:

- **Archivo a modificar:** `config.php`
- **Cambios a realizar:** Actualiza las credenciales de la base de datos con las que creaste en tu hosting.

    $servername = "localhost"; // Generalmente es 'localhost', pero conf&iacute;rmalo en tu hosting.
    $username   = "NOMBRE_DE_USUARIO_DEL_HOSTING";
    $password   = "CONTRASE&Ntilde;A_DEL_HOSTING";
    $dbname     = "NOMBRE_DE_LA_BD_DEL_HOSTING";

**Importante:** Tambi&eacute;n revisa y actualiza las credenciales SMTP en este mismo archivo si planeas usar la funcionalidad de env&iacute;o de correos desde el servidor en vivo.

----------------------------------------
4. SUBIDA DE ARCHIVOS
----------------------------------------

1.  Con&eacute;ctate a tu hosting usando un cliente FTP (como FileZilla) o el Administrador de Archivos del panel de control.
2.  Navega al directorio ra&iacute;z de tu sitio web (normalmente `public_html`).
3.  Sube **todos los archivos y carpetas** del proyecto `zapp_citas` a este directorio.
    - **Recomendaci&oacute;n:** Para ahorrar espacio y tiempo, puedes omitir la subida de las carpetas `backup*`.

----------------------------------------
5. VERIFICACI&Oacute;N FINAL
----------------------------------------

Una vez subidos los archivos, abre tu dominio en el navegador y realiza pruebas exhaustivas:
- Intenta iniciar sesi&oacute;n en el portal del propietario y del cliente.
- Navega por todas las secciones (Agenda Diaria, Clientes, Mi Negocio, etc.).
- Realiza una acci&oacute;n que interact&uacute;e con la base de datos (ej. editar un cliente) para confirmar que la conexi&oacute;n es correcta.

6. ESTRUCTURA DE ARCHIVOS (SPA DEL PROPIETARIO)
----------------------------------------

La aplicaci&oacute;n del propietario (`spa_owner.php`) sigue una arquitectura modular moderna para facilitar su mantenimiento y escalabilidad.

**Archivo Principal (El "Cerebro"):**
- `app_owner.js`: Orquesta toda la aplicaci&oacute;n. Carga las traducciones, verifica la sesi&oacute;n, importa todos los m&oacute;dulos y gestiona la navegaci&oacute;n entre vistas.

**M&oacute;dulos de Vistas y L&oacute;gica (`/js/modules/`):**
- `auth.js`: Gestiona el inicio de sesi&oacute;n, cierre de sesi&oacute;n y recuperaci&oacute;n de contrase&ntilde;a.
- `agenda.js`: Renderiza la vista principal de la agenda diaria.
- `calendario.js`: Renderiza la vista del calendario mensual/semanal (FullCalendar).
- `disponibilidad.js`: Muestra los slots de tiempo libres y ocupados para un d&iacute;a.
- `clientes.js`: Gestiona la lista y los formularios de creaci&oacute;n/edici&oacute;n de clientes.
- `servicios.js`: Gestiona la lista y los formularios de creaci&oacute;n/edici&oacute;n de servicios.
- `negocio.js`: Gestiona el formulario de configuraci&oacute;n del negocio (datos, direcci&oacute;n, horarios).
- `perfil.js`: Gestiona el formulario del perfil del propietario (cambio de contrase&ntilde;a, etc.).
- `citas.js`: Contiene los formularios para crear y editar citas.
- `ui.js`: Controla elementos de la interfaz de usuario como la barra de navegaci&oacute;n y el reloj.

**APIs de Backend (`/api_*.php`):**
La SPA se comunica con el servidor a trav&eacute;s de una serie de archivos PHP que act&uacute;an como una API REST. Cada uno tiene una funci&oacute;n espec&iacute;fica (ej. `api_owner_citas.php`, `api_owner_clientes.php`, etc.) y devuelve datos en formato JSON.

----------------------------------------
7. NOTAS DE ARQUITECTURA: ESTRATEGIAS DE INTERNACIONALIZACI&Oacute;N (i18n)
----------------------------------------

La aplicaci&oacute;n utiliza dos estrategias diferentes para manejar m&uacute;ltiples idiomas (ES/EN), dependiendo del tipo de interfaz.

**Estrategia 1: Aplicaci&oacute;n Tradicional (Ej: index.php, zapp_citas)**

- **C&oacute;mo funciona:** Cuando se solicita una p&aacute;gina (ej. `index.php?lang=en`), el servidor PHP se ejecuta, carga el archivo de idioma correspondiente desde el disco (`/languages.php`) y construye la p&aacute;gina HTML completa con los textos ya traducidos antes de enviarla al navegador.
- **Traducci&oacute;n:** Ocurre en el **servidor (backend)**.
- **Cambio de Idioma:** Requiere una **recarga completa de la p&aacute;gina** para que el servidor pueda generar un nuevo HTML.

**Estrategia 2: Single-Page Application (SPA) (Ej: spa_owner.php, spa_client.php)**
- **C&oacute;mo funciona:** El servidor env&iacute;a una p&aacute;gina HTML m&iacute;nima (`spa_owner.php`) que act&uacute;a como un "contenedor". El c&oacute;digo JavaScript (`app_owner.js`) toma el control total de la interfaz dentro del navegador.
- **Traducci&oacute;n:**
  1. JavaScript detecta el idioma en la URL (`?lang=en`).
  2. Realiza una petici&oacute;n a la API `api_get_translations.php` para obtener el "diccionario" de traducciones en formato JSON.
  3. JavaScript almacena este diccionario en memoria (en el objeto `context.T`).
  4. A partir de ese momento, JavaScript construye y actualiza din&aacute;micamente todas las vistas (login, agenda, clientes, etc.) directamente en el navegador, utilizando los textos del diccionario cargado.
- **Cambio de Idioma:** Requiere una recarga de la p&aacute;gina para que la SPA solicite el nuevo diccionario de idioma a la API.

**&iquest;Por qu&eacute; la diferencia?**
La arquitectura SPA es m&aacute;s r&aacute;pida y fluida para el usuario. Una vez cargada, la navegaci&oacute;n entre vistas (ej. de "Mi Agenda" a "Mis Clientes") es instant&aacute;nea porque no necesita pedir una p&aacute;gina nueva al servidor, solo actualiza una parte de la pantalla. Esto crea una experiencia de usuario similar a la de una aplicaci&oacute;n de escritorio o m&oacute;vil.
