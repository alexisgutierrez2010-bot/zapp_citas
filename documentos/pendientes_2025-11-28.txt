==================================================
TAREAS PENDIENTES Y RECOMENDACIONES - ZAPP CITAS
==================================================

Fecha: 28 de Noviembre de 2025

Este documento resume las tareas de optimización y corrección recomendadas para consolidar la aplicación antes de su despliegue en producción.

----------------------------------------
1. (CRÍTICO) Estandarizar Nombres de Archivos (Case-Sensitivity)
----------------------------------------

*   **Problema:** En varios archivos del panel de administración (ej. `clientes_lista.php`, `usuarios_lista.php`), se está incluyendo el guardián de sesión con una 'A' mayúscula: `require_once 'Auth_check.php';`. Sin embargo, el nombre real del archivo es `auth_check.php` (con 'a' minúscula).

*   **Riesgo:** Esto funciona en tu entorno local (XAMPP en Windows) porque Windows no distingue entre mayúsculas y minúsculas en los nombres de archivo. Sin embargo, los servidores de hosting (que usan Linux) SÍ distinguen. Al subir el proyecto, esto causará un **error fatal de PHP** y el panel de administración no funcionará.

*   **Recomendación:** Estandarizar todas las llamadas a `require_once 'auth_check.php';` usando minúsculas para que coincida con el nombre del archivo. Esto es crucial para que la aplicación funcione en el hosting.

----------------------------------------
2. (RECOMENDADO) Optimizar la Actualización de Citas Vencidas
----------------------------------------

*   **Problema:** El script `api_owner_horario_disponible.php` (que alimenta la vista "Disponibilidad del Día") ejecuta una consulta `UPDATE` para marcar las citas como 'Vencida' cada vez que un propietario consulta la disponibilidad.

*   **Riesgo:** Aunque funciona, es ineficiente. Si muchos propietarios consultan su agenda simultáneamente, se estarán ejecutando múltiples consultas `UPDATE` innecesarias sobre la misma tabla, lo que puede ralentizar la base de datos y la respuesta de la API.

*   **Recomendación:** Mover esta lógica a una tarea programada en el servidor (conocida como "Cron Job"). Se puede crear un script PHP separado (ej. `cron_actualizar_vencidas.php`) que solo contenga esa consulta `UPDATE` y configurar el hosting para que lo ejecute automáticamente cada hora.

*   **Beneficios:**
    - Mejora el rendimiento de la API `api_owner_horario_disponible.php`.
    - Reduce la carga sobre la base de datos.
    - Es una práctica de desarrollo más limpia y escalable.
